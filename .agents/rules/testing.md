# 修改、測試與部署規則

## 適用範圍

修改程式、CSS、HTML 模板、資料、圖片、測試或部署相關路徑時必讀。純文件變更可依下方縮小驗證。

## 修改前

- 先執行 `git status --short`，保留使用者與其他工作中的未提交修改；不要覆蓋或清理無關檔案。
- 以 `rg` 搜尋既有 selector、資料 key、事件、建立器與測試，先理解目前資料流。
- 視需要讀 `tests/README.md`；捲動、動畫、觸控與事件代理測試尤其要遵守其中 CDP 陷阱。
- 小幅修正優先改既有結構，不重寫整頁或順手整理無關程式。

## 必要驗證

程式、互動、版面、模板或資料修改完成後至少執行：

```bash
git diff --check
node tests/run.mjs
```

- 完整測試以多個 headless Chrome 平行執行；需要除錯時用 `node tests/run.mjs <關鍵字> --jobs=1`。
- 文件專用變更至少執行 `git diff --check`，並檢查所有引用的本地路徑存在；不必為文字重構跑完整瀏覽器回歸。
- 測試通過不等於視覺正確；依變更範圍人工檢查首頁、國家頁與代表性地區頁。

## Bug 與新測試

- 修 bug 時補上可重現該問題的回歸測試。
- 新增測試後，刻意暫時破壞對應程式，確認測試確實失敗，再恢復修正並重跑；不要留下只會通過的無效斷言。
- 不用固定 `sleep()` 等動畫結果。等待實際狀態、hash、class、位置穩定或條件成立。
- 量測捲動位置前先等待頁面穩定；測事件代理時使用真實滑鼠／觸控操作，不用 `dispatchEvent` 假造 target。
- 新增逐像素捲動相等或動畫中途取樣的群組時標記 `{ serial: true }`，避免平行 Chrome 的 CPU 競爭造成偶發漂移。
- 斷言優先檢查行為與可見結果，不要只鎖死某個內部實作；但單一來源、模板結構與路徑等架構契約可以直接檢查。

## 覆蓋情境

互動或頁面修改至少考慮：

- 桌面滑鼠 hover／click。
- 鍵盤 Tab、Enter、Space、Escape 與關閉後 focus 還原。
- 手機／平板 touch、`hover: none`、橫直向與殘留 `:hover`。
- `prefers-reduced-motion`。
- 空資料、錯誤資料與動態插入，而不只是初始 HTML seed。
- 亮色／暗色主題、viewport 溢出、單一垂直捲動容器與相對路徑。

測試無法完全涵蓋，仍需人工確認：

- amCharts CDN 初始化失敗時首頁其他內容仍存在。
- 真實 iOS Safari 的觸控與殘留 hover 手感。
- 光暈、陰影、遮罩、文字對比與動畫是否符合設計意圖。
- GitHub Pages 的大小寫與路徑和本機完全一致。

## GitHub Pages

- 部署來源是 `main` branch，網站維持可直接服務的靜態檔案。
- 不加入建置產物、本機絕對路徑或敏感資訊。
- `tests/` 是 repository 的一部分並應提交；GitHub Pages 只服務靜態檔案，不會執行 Node 測試。
- 測試暫存頁以 `_test-` 前綴並保持在 `.gitignore`。
- 推送前檢查全部 HTML、CSS、JavaScript 與圖片的相對路徑，尤其三種模板的不同目錄深度。
